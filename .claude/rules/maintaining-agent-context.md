# Maintaining agent context (.claude/)

> How to keep CLAUDE.md, AGENTS.md and `.claude/` consistent and useful.

## Layout

| Location                | Purpose                                                                                                                                                  |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLAUDE.md`             | Always loaded: imports `AGENTS.md` (`@AGENTS.md`) and adds Claude-specific working rules and the list of skills, agents and MCP servers. Keep short.     |
| `AGENTS.md`             | Tool-agnostic orientation for humans and AI contributors (product, entrypoints, constraints, commands, hooks, CI); links to the rules.                   |
| `.claude/rules/`        | Topical rules. Every rule has `paths` frontmatter, so it loads only when matching files are touched.                                                     |
| `.claude/skills/`       | Skills (`<name>/SKILL.md`), loaded on demand or invoked as `/<name>`: `verify`, `release`, `playwright`, `e2e-review`.                                   |
| `.claude/agents/`       | Read-only subagents (`code-reviewer`, `qa-engineer`, `e2e-reviewer`) and the generated `playwright-test-{planner,generator,healer}`.                     |
| `.claude/settings.json` | Shared permissions (allow / ask / deny), attribution off, the enabled plugin marketplace. Personal overrides go to the gitignored `settings.local.json`. |
| `.mcp.json`             | Project MCP servers: `chrome-devtools` (pinned to an exact version) and `playwright-test` (generated).                                                   |

## Rules of thumb

- A new rule needs `paths` frontmatter; only `CLAUDE.md` / `AGENTS.md` are always loaded. Prose such as "Applies to: ..." does not scope anything.
- Write what Claude cannot derive from the code; link to real files instead of copying them. Do not repeat the same fact in several files: `AGENTS.md` gives the overview, a rule gives the details of one topic.
- Requirements that can be enforced (blocked commands, formatting, checks) belong in `.claude/settings.json`, hooks, scripts or CI, not only in prose.
- Skill descriptions are in the third person and say what the skill does and when to use it.
- Remove outdated guidance promptly; stale rules are worse than no rules.
- Write in simple, explicit English; every command, path and value must match the code.

## Keeping things in sync

- When an npm script, manifest key, permission, storage key or shared API changes, update `README.md`, `AGENTS.md`, the matching rule in `.claude/rules/` and `.claude/skills/verify/SKILL.md` if the checks changed.
- When a shortcut, setting or supported page is added, follow the checklist in [extension-architecture.md](extension-architecture.md) and update `README.md`, `LISTING.md` and `RELEASE_NOTES.md` too.
- When a Bandcamp selector changes, update [bandcamp-dom.md](bandcamp-dom.md); when a message code or port changes, [messaging.md](messaging.md); when the batch download flow changes, [batch-download.md](batch-download.md).
- When the release steps, the zip names or the publish workflows change, update `.claude/skills/release/SKILL.md` and the checklist in `.claude/agents/qa-engineer.md`.
- When the `web-ext lint` warnings change, update [firefox.md](firefox.md) and `.claude/skills/verify/SKILL.md` together.
- When tests, test fixtures, test npm scripts or the permissions for them in `.claude/settings.json` change, update [testing.md](testing.md), `.claude/skills/playwright/SKILL.md`, `.claude/skills/verify/SKILL.md`, the `qa-engineer` checklist and the tests section of `README.md`.
- The `playwright-test-*` agents and the `playwright-test` entry in `.mcp.json` are generated by `npx playwright init-agents --loop=claude --project=e2e`: regenerate after every Playwright update, do not hand-edit them. The command overwrites `.mcp.json`, so re-add `chrome-devtools` (check with `git diff .mcp.json`).
- After moving or renaming files, check that every relative link in `CLAUDE.md`, `AGENTS.md` and `.claude/**/*.md` still resolves.
